Problem

StorageService exposes 20+ thin CRUD functions for local storage, which useStudyData mirrors identically line-by-line, creating two shallow pass-through modules with zero leverage.

Solution

Unify state management and persistence into a single deep Study Store module hiding storage details behind high-level domain interfaces.

Wins

  • locality: state mutations and reactive sync reside in one module
  • leverage: callers invoke domain actions without pass-through hooks
  • testability: module tested through interface without mock storage

Problem

AIService duplicates network fetch error-handling and fallback generation across 7 methods, leaking transport details and mock logic across the entire module.

Solution

Introduce a clean AiAdapter interface with two adapters: HttpRemoteAiAdapter and ClientFallbackAiAdapter, hiding transport and fallback mechanics behind a deep AI client module.

Wins

  • locality: network handling and mock fallback isolated in adapters
  • leverage: testable with mock adapter without global fetch overrides
  • two adapters justify seam: HTTP in production, offline fallback in tests/offline

Problem

Exam result recording, grading calculations, and diagnostic aggregation are split across utility functions, storage getters, and UI view logic.

Solution

Encapsulate attempt recording, grading evaluation, score distribution, and topic accuracy inside a deep Assessment Engine module.

Wins

  • locality: diagnostic calculations and attempt history concentrate in one place
  • leverage: UI receives ready-to-render analytics summaries
  • testability: full assessment lifecycle verified through a single interface
Top Recommendation

Consolidate Persistence & Reactive Sync into a Deep Study Store Module

The current separation between StorageService (a 20+ method static CRUD wrapper) and useStudyData (a React hook that mirrors every single StorageService method) represents the highest architectural friction in the codebase. Both are shallow pass-through layers. Collapsing them into a deep Study Store Module will yield maximum locality for state persistence and maximum leverage for callers and tests.
